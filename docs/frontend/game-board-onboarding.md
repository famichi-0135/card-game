# ゲームボードオンボーディング

## 目的

初めて対戦する利用者が、ゲーム開始前にカード配置とサポート操作を確認できるようにする。ガイドの閲覧そのものによって実ゲームのフェーズ制限時間を消費させない。

## 表示タイミング

- 待機部屋には、初回判定にかかわらず「遊び方を見る」を表示する。
- ブラウザに未完了記録がない初回利用者は、`waiting`または`preparing`の待機部屋を開くと自動表示する。
- ガイドの完了、スキップ、Escまたは閉じる操作後に待機部屋へ戻る。ガイドを終えても準備完了は自動送信しない。
- `preparing`では双方が「準備完了」を送信した後にだけゲームを生成し、`/games/:gameId`へ遷移する。したがってガイド中は実ゲームの制限時間を開始しない。

## 表示内容

Driver.jsをオンボーディング開始時に読み込み、待機部屋上の読み取り専用ゲームボードプレビューを案内する。プレビューは既存の`FixtureGameBoard`を利用するが、ゲームコマンド、WebSocket、実ゲームの状態を使用しない。

説明は次の8段階とする。

1. ラウンド、フェーズ、制限時間
2. 手札とカード詳細
3. 相手・自分のバトルゾーン
4. 空の攻撃グループ枠へのドラッグ
5. 既存の攻撃グループへの連鎖
6. 配置フェーズ中の捨て札操作
7. サポートフェーズ中のサポートゾーンと対象選択
8. フェーズ終了と、クリック・Enterによるドラッグ以外の操作

説明文は[ゲームルール定義](../game/rule-definition.md)と矛盾させない。クライアントで操作候補を案内しても、最終的な受理判定はサーバーが行う。

## 操作とアクセシビリティ

- `showProgress`、キーボード操作、前後移動、スキップ、完了を有効にし、日本語の操作文言を使う。
- `prefers-reduced-motion: reduce`のときはDriver.jsのアニメーションを無効にする。
- ガイド中は対象盤面の操作を無効にする。終了後は、開始元の「遊び方を見る」ボタンへフォーカスを戻す。
- 説明対象は表示文言やTailwindクラスに依存せず、`data-onboarding-target`で指定する。対象が欠けた場合はステップを黙って飛ばさない。

## 初回表示の保存

ブラウザ単位で`localStorage`の`disastar:onboarding:game-board:v1`に`completed`または`skipped`を保存する。保存済みなら自動表示しないが、「遊び方を見る」からは常に再表示できる。ストレージが使えない環境では自動表示を行わず、待機部屋と手動表示を継続利用できる。

内容を大幅に変更する場合はキーを`v2`へ上げる。アカウント単位の同期や端末間の同期は初期スコープに含めない。
